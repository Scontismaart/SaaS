Architettura Tecnica, Invarianti e Pipeline di Esecuzione

Guida approfondita per architetti software, ingegneri e sviluppatori sul funzionamento interno e le garanzie di sicurezza di Melpis.

Cosa permette di fare

Questa sezione descrive l'infrastruttura sottostante, il ciclo di vita dell'ingestione asincrona dei webhook, la gestione dell'isolamento multi-tenant a livello applicativo e di database, e gli 11 Invarianti Non Negoziabili che governano il runtime di Melpis.

Stack Tecnologico

  • Backend API: Python 3.11+, FastAPI (asincrono con uvicorn), Pydantic v2.
  • Database Relazionale & Vettoriale: PostgreSQL 15+ con estensione pgvector (vettori 384d per RAG e cache semantica), driver ad alte prestazioni asyncpg.
  • Integrazioni Canali: Meta Cloud API (WhatsApp Business Graph API v21.0, Instagram Direct Messaging API), Google Calendar API v3, Google Business Profile API.
  • Orchestratore AI & Provider: LiteLLM proxy con routing su modelli Llama 3/3.3 ad altissima velocità (Groq LPUs) e fallback su modelli frontier.
  • Frontend: Vanilla JavaScript ES6+, zero framework build-step pesanti, Nginx containerizzato.

Gli 11 Invarianti Architetturali Non Negoziabili

1

1. Tenant Isolation Assoluta

Ogni tabella tenant-scoped ha la colonna organization_id. L'isolamento applicativo viene validato in ogni singola query; le policy Row-Level Security (RLS) fungono da defense-in-depth aggiuntiva.

2

2. Ambito Dati Provabile

Nessun record può esistere senza un'appartenenza diretta o provabilmente derivabile a una specifica organizzazione.

3

3. Latenza Webhook Meta < 200ms

Il webhook di ricezione (POST /webhooks/whatsapp) effettua la verifica della firma HMAC-SHA256, persiste il payload grezzo nella tabella code e restituisce immediatamente HTTP 200 OK a Meta. La generazione AI non blocca mai la risposta al webhook.

4

4. Idempotenza Globale

Tutti gli eventi con effetti collaterali esterni (invio messaggi WhatsApp, prenotazioni calendario, escalation, addebiti Stripe) sono protetti da chiavi di idempotenza (idempotency_key = hash(org_id, message_id, action)).

5

5. Nessuna Azione Privilegiata Diretta da LLM

L'output del modello linguistico non effettua direttamente mutazioni sul database, transazioni finanziarie o conferme vincolanti. Tutte le azioni passano da validatori deterministici rigidi.

6

6. Fail-Closed Opt-Out

Al rilevamento di una parola chiave di disiscrizione (STOP, BASTA), il sistema persiste l'evento, aggiorna lo stato, registra l'audit e blocca irreversibilmente future trasmissioni promozionali verso il contatto.

7

7. Pipeline Guardrail Deterministica

Ogni risposta generata prima di essere inviata al cliente attraversa il PriceValidator, il verificatore di allucinazioni e il filtro di conformità.

8

8. Governance Costi e Kill-Switch Automatico

Ogni chiamata AI registra org_id, modello, token di input/output, latenza e costo stimato. Un kill-switch automatico blocca le chiamate in caso di saturazione del budget mensile.

9

9. Tracciabilità ed Evidenza Strutturata

Tutti i log utilizzano formattazione JSON strutturata con organization_id, conversation_id e trace_id, mascherando i dati sensibili (PII).

10

10. Protezione Segreti a Riposo

I token API permanenti di Meta, le chiavi Stripe e le chiavi Google sono crittografati a riposo tramite Fernet (AES-128-CBC) e mai esposti nei log applicativi o al frontend.

11

11. Escalation Umana Inderogabile (HITL)

L'assistente garantisce sempre la transizione della chat a un operatore umano qualora richiesto o in caso di dubbio operativo.

Pipeline del Messaggio Inbound

Il percorso di un messaggio dal cliente finale al telefono fino alla risposta automatizzata segue un ciclo rigoroso:

Flusso di Ingestione (Diagramma a Blocchi) 
[Cliente WhatsApp]
       │
       ▼
[Meta Cloud API] ──(Webhook HTTPS con HMAC-SHA256)──► [FastAPI Endpoint]
                                                             │ (HTTP 200 immediato < 50ms)
                                                             ▼
                                                    [InboundQueue PostgreSQL]
                                                             │
                                                             ▼ (SKIP LOCKED Worker)
                                                    [InboundProcessor]
                                                             ├── 1. Controllo Opt-Out
                                                             ├── 2. Verifica Stato Claim (ai_sospesa?)
                                                             ├── 3. Cache Semantica FAQ (0 token)
                                                             ├── 4. RAG Retrieval pgvector
                                                             ├── 5. Generazione LLM LiteLLM
                                                             ├── 6. Guardrail PriceValidator
                                                             └── 7. Outbound Meta API Dispatch

Worker Asincroni e SKIP LOCKED

Per prevenire race condition o doppie risposte quando arrivano più messaggi contemporanei dal medesimo contatto, il worker di elaborazione acquisisce il messaggio utilizzando la clausola PostgreSQL FOR UPDATE SKIP LOCKED:

Python (src/whatsapp/inbound_processor.py) 
async def fetch_next_inbound_message(db_pool):
    query = """
        SELECT id, organization_id, payload, channel
        FROM inbound_messages_queue
        WHERE status = 'pending'
        ORDER BY created_at ASC
        LIMIT 1
        FOR UPDATE SKIP LOCKED;
    """
    async with db_pool.acquire() as conn:
        async with conn.transaction():
            row = await conn.fetchrow(query)
            if row:
                await conn.execute("UPDATE inbound_messages_queue SET status = 'processing' WHERE id = $1", row['id'])
                return row
    return None

Configurazione di Produzione

La distribuzione è orchestrata tramite Docker Compose:

  • web: Reverse proxy Nginx con compressione Gzip, cache header per asset statici e gestione clean routing.
  • api: Servizio FastAPI containerizzato con 4 worker uvicorn.
  • db: PostgreSQL 15 con estensione pgvector montata su volume persistente ad alte prestazioni.
